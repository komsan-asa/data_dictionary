# Data Dictionary

ระบบเก็บ Data Dictionary แยกตามโปรเจ็ค: ดึงโครงสร้างตารางจากฐานข้อมูลจริง แล้วให้คนหรือ Claude เติมความหมายของตารางและคอลัมน์

- ฐานข้อมูลของระบบ: `db_data_dictionary` (MySQL 5.7+ / MariaDB 10.2+)
- ฐานข้อมูลต้นทางที่ดึงโครงสร้างได้: MySQL / MariaDB และ PostgreSQL
- ต้องการ PHP 7.4 ขึ้นไป พร้อม extension `pdo_mysql`, `openssl`, `mbstring` (และ `pdo_pgsql` ถ้าจะดึงจาก PostgreSQL)

## ติดตั้ง

1. สร้างฐานข้อมูล: `mysql -u root -p < database/schema.sql`
2. สร้างผู้ใช้ฐานข้อมูลสำหรับระบบนี้ เช่น
   ```sql
   CREATE USER 'dd_user'@'localhost' IDENTIFIED BY 'รหัสผ่าน';
   GRANT SELECT, INSERT, UPDATE, DELETE ON db_data_dictionary.* TO 'dd_user'@'localhost';
   ```
3. แก้ `config/config.php` ใส่ host, user, รหัสผ่าน (ค่า `app_key` สุ่มไว้ให้แล้ว ห้ามเปลี่ยนหลังเริ่มใช้งาน)
4. เปิด `http://<เครื่องแม่ข่าย>/data_dictionary/` ครั้งแรกระบบจะให้สร้างผู้ดูแลคนแรก

## ใช้งาน

เข้าสู่ระบบแล้วจะเจอหน้า **ภาพรวม** (กลับมาได้จากปุ่ม "ภาพรวม" บนสุดของแถบซ้าย) แสดงความคืบหน้าของทุกโปรเจ็ค:

- สัดส่วนคอลัมน์ที่มีความหมายแล้ว จำนวนที่ยังต้องเขียน จำนวนตาราง ข้อเสนอรอพิจารณา และความหมายที่ระบบเดาแต่ยังไม่มีคนยืนยัน
- ตารางโปรเจ็ค พร้อมแถบสีบอกว่าความหมายมาจากไหน (คนเขียน, นำเข้าทาง API, comment ในฐานข้อมูล, ระบบเดา, ยังว่าง) ชี้หรือโฟกัสที่แถบเพื่อดูจำนวน หรือกด "ดูเป็นตัวเลข" กดที่แถวเพื่อเปิดโปรเจ็ค
- ตารางที่มีข้อเสนอรอพิจารณา กดเพื่อไปตรวจได้ทันที
- ผู้เขียนความหมาย (จำนวนคอลัมน์ต่อคน) และกิจกรรมล่าสุด 10 รายการ

แถบซ้ายแสดงรายการโปรเจ็ค พร้อมช่องค้นหา ตัวกรอง และการเรียง:

- **ค้นหา** จากชื่อ รหัส รายละเอียด ชื่อฐานข้อมูลหรือ host ต้นทาง พิมพ์หลายคำได้ (ต้องพบทุกคำ) กด Enter เพื่อเปิดโปรเจ็คแรกที่พบ กด Esc เพื่อล้างคำค้น
- **กรอง** ทุกโปรเจ็ค, ยังไม่ครบ, ครบแล้ว, มีข้อเสนอรอพิจารณา, ยังไม่เคยซิงค์
- **เรียง** ตามชื่อ, คืบหน้าน้อยก่อน, คืบหน้ามากก่อน, ซิงค์ล่าสุดก่อน

ตัวกรองและการเรียงถูกจำไว้ในเบราว์เซอร์ของแต่ละคน ส่วนคำค้นไม่ถูกจำ การค้นและกรองนี้มีผลกับรายการในแถบซ้ายเท่านั้น ตัวเลขในหน้าภาพรวมยังนับทุกโปรเจ็ค

ขั้นตอนทำงานกับแต่ละโปรเจ็ค:

1. **เพิ่มโปรเจ็ค** ตั้งรหัส (เช่น `hosxp`) และค่าการเชื่อมต่อฐานข้อมูลต้นทาง แล้วกด "บันทึกและทดสอบการเชื่อมต่อ"
2. **ซิงค์โครงสร้าง** ระบบอ่านตาราง คอลัมน์ ชนิดข้อมูล คีย์ index และ comment เข้ามา กดซ้ำได้ทุกครั้งที่โครงสร้างเปลี่ยน
3. **เขียนความหมาย** เลือกตาราง พิมพ์ในช่อง ระบบบันทึกเองเมื่อออกจากช่อง (Enter = บันทึกแล้วไปแถวถัดไป)
4. **ให้ Claude ช่วย** กด "API สำหรับ Claude" สร้าง API key แล้วคัดลอกข้อความไปวางใน `CLAUDE.md` ของโปรเจ็คนั้น (รายละเอียดใน `CLAUDE_GUIDE.md`)
5. **ส่งออก** เป็น Markdown, CSV หรือ JSON
6. **โคลนโปรเจ็ค** กด "ตั้งค่า" แล้วกด "โคลนโปรเจ็ค" เพื่อสร้างโปรเจ็คใหม่ที่มีตาราง คอลัมน์ และความหมายทั้งหมดเหมือนโปรเจ็คเดิม เหมาะกับฐานข้อมูลอีกชุดที่โครงสร้างเดียวกัน (เช่น ระบบเดียวกันของอีกหน่วยงาน หรือฐานทดสอบ) โคลนแล้วแก้ค่าการเชื่อมต่อเป็นฐานข้อมูลใหม่ แล้วกดซิงค์ ตารางหรือคอลัมน์ที่ฐานใหม่ไม่มีจะถูกทำเครื่องหมาย "ถูกลบ" โดยคำอธิบายยังอยู่ ไม่คัดลอก API key, ประวัติ, ตัวอย่างข้อมูลและข้อเสนอรอพิจารณา

### เดาความหมายด้วยกฎในระบบ

ระบบเดาความหมายเองได้โดยไม่ส่งข้อมูลออกนอกเครื่องแม่ข่าย ทุกอย่างเป็น "ข้อเสนอ" ให้คนพิจารณา ไม่ทับสิ่งที่คนเขียนไว้

| ปุ่ม | อยู่ที่ | ทำอะไร |
|---|---|---|
| **ตีความจากข้อมูลจริง** | หน้าตาราง | อ่าน 50 แถวล่าสุดของตาราง ดูว่าแต่ละคอลัมน์เก็บข้อมูลลักษณะใด ตามคอลัมน์รหัสไปดูตารางที่อ้างอิง แล้วเก็บตัวอย่างข้อมูลกับข้อเสนอไว้รอพิจารณา |
| **เดาจากชื่อคอลัมน์** | หน้าตาราง | ใช้ชื่อคอลัมน์อย่างเดียว ไม่อ่านข้อมูล ข้อเสนอชุดนี้ไม่ถูกเก็บ |
| **เดาความหมาย** | แถบบนของโปรเจ็ค | เดาจากชื่อทั้งโปรเจ็คในครั้งเดียว นับให้ดูก่อน รายการที่เติมมีป้าย "ระบบเดา" และกด "ล้างที่ระบบเดาไว้" เพื่อย้อนกลับได้ |

#### ตีความจากข้อมูลจริง

1. อ่านแถวล่าสุดของตาราง (เรียงตาม primary key ย้อนหลัง) จำนวน 50 แถว ปรับได้ด้วย `sample_rows`
2. ดูรูปแบบของค่าในแต่ละคอลัมน์ ถ้าบอกความหมายได้ชัดจะเสนอเป็นความหมาย เช่น เลขประจำตัวประชาชน (ตรวจหลักสุดท้าย) เบอร์โทรศัพท์มือถือ อีเมล ที่อยู่ ชื่อบุคคลพร้อมคำนำหน้า คำนำหน้าชื่อ เพศ วันที่ที่เก็บเป็นข้อความ ปี พ.ศ. พิกัด JSON (พร้อมรายชื่อคีย์) ชื่อไฟล์ ค่า hash
3. คอลัมน์ที่เป็นรหัส ระบบหาตารางที่ชื่อเกี่ยวข้องกับชื่อคอลัมน์ (เช่น `ward` กับตาราง `ward`, `status_id` กับ `coc_status`, `admdoctor` กับ `doctor`) แล้วตรวจกับข้อมูลจริงว่าค่าในคอลัมน์มีอยู่ใน primary key ของตารางนั้นอย่างน้อย 80% ถ้าใช่จะเสนอ "อ้างอิงไปที่" และอ่านชื่อของแต่ละรหัสจากตารางนั้นมาเป็น "ค่าที่เป็นไปได้" เช่น `01=อายุรกรรมชาย, 02=อายุรกรรมหญิง`
4. ถ้าข้อมูลบอกความหมายไม่ได้ ใช้กฎจากชื่อคอลัมน์ (ดูหัวข้อถัดไป) ถ้ายังไม่ได้อีก จะเสนอเฉพาะลักษณะข้อมูล เช่น "รหัสตัวเลข 2 หลัก" เป็นข้อเสนอสีเทา ซึ่งปุ่ม "ใช้ทั้งหมด" ไม่รวม
5. เก็บผลไว้ที่คอลัมน์ จึงเปิดตารางครั้งหน้าได้เลยโดยไม่ต้องอ่านฐานข้อมูลต้นทางใหม่ ตัวกรอง "รอพิจารณา" ในรายการตารางแสดงตารางที่ยังมีข้อเสนอค้างอยู่

สิ่งที่แสดงใต้แต่ละคอลัมน์:

- **ข้อมูลที่พบ** คำบรรยายลักษณะข้อมูล จำนวนค่าที่ไม่ซ้ำ และจำนวนแถวที่ว่าง
- **ตัวอย่างค่าที่พบซ้ำ** ค่าที่พบตั้งแต่ 2 แถวขึ้นไป เรียงจากที่พบบ่อย สูงสุด 12 ค่า พร้อมจำนวนแถวและชื่อของรหัส (ถ้ามีตารางอ้างอิง) ให้คนดูแล้วเดาความหมายเองได้
- **ข้อเสนอ** กรอบเส้นประใต้ช่อง กด "ใช้" เพื่อบันทึก หรือ "×" เพื่อทิ้ง

ข้อมูลส่วนบุคคล:

- การวิเคราะห์ทำบนเครื่องแม่ข่ายทั้งหมด ระบบอ่านทุกคอลัมน์ (ยกเว้นข้อมูลไบนารี) เพื่อดูรูปแบบ
- ค่าดิบถูกเก็บและแสดงเป็นตัวอย่างเฉพาะคอลัมน์รหัส สถานะ ตัวเลข และข้อความสั้นที่มีค่าซ้ำกัน
- ไม่เก็บและไม่แสดงค่าของคอลัมน์ที่ชื่อหรือข้อมูลบ่งว่าเป็นข้อมูลส่วนบุคคลหรือข้อความอิสระ เช่น ชื่อ เลขบัตร HN ที่อยู่ โทรศัพท์ อีเมล พิกัด หมายเหตุ (รายการชื่ออยู่ที่ `PRIVATE_NAME` ใน `src/Guesser.php`) และไม่เก็บค่าของ primary key หรือคอลัมน์ unique
- ไม่ดึงชื่อจากตารางรายชื่อบุคคล (เช่น `patient`, `doctor`, `user`) มาเป็นคำแปลของรหัส
- ตัวอย่างข้อมูลแสดงเฉพาะผู้ใช้ที่เข้าสู่ระบบหน้าเว็บ ไม่ส่งให้ผู้เรียกด้วย API key และไม่อยู่ในไฟล์ส่งออก

ข้อจำกัด:

- 50 แถวเป็นตัวอย่างเล็ก ค่าที่ไม่อยู่ใน 50 แถวล่าสุดจะไม่ปรากฏ รายการ "ค่าที่เป็นไปได้" จึงอาจไม่ครบ
- การจับคู่ตารางอ้างอิงเป็นการเดา ตารางที่ชื่อไม่เกี่ยวกับชื่อคอลัมน์เลยจะหาไม่เจอ และรหัสตัวเลขเล็ก ๆ อาจตรงกับตารางที่ชื่อคล้ายกันโดยบังเอิญ
- ไม่อ่านวิว จำกัดเวลาอ่าน 20 วินาที และผู้ใช้ฐานข้อมูลของโปรเจ็คต้องมีสิทธิ์ `SELECT` บนตารางนั้นและตารางที่อ้างอิง
- ปิดความสามารถนี้ทั้งระบบได้ด้วย `'allow_value_sampling' => false` ใน `config/config.php`

ที่เก็บผลคือคอลัมน์ `sample_json`, `suggest_json`, `sampled_at` ของตาราง `dd_columns` ระบบเพิ่มให้เองตอนกดปุ่มครั้งแรก ถ้าผู้ใช้ฐานข้อมูลของระบบไม่มีสิทธิ์ `ALTER` หน้าเว็บจะแจ้งว่า "ยังไม่ได้เก็บผล" ให้รัน `database/migrate_20261110_samples.sql` หนึ่งครั้ง

#### กฎจากชื่อคอลัมน์

เรียงตามลำดับที่ใช้:

1. **ชื่อเดียวกัน** คอลัมน์ชื่อเดียวกันในโปรเจ็คที่มีคนเขียนความหมายไว้แล้ว (ใช้เมื่อความหมายเดียวกันถูกใช้เกิน 60% ของคอลัมน์ชื่อนั้น และไม่ใช้กับชื่อกว้าง ๆ) เขียนความหมายของ `hn` ครั้งเดียว จึงเติมได้ทุกตารางที่มี `hn`
2. **พจนานุกรม** ชื่อที่พบบ่อยทั้งแบบทั่วไปและของระบบโรงพยาบาล เช่น `created_at`, `cid`, `hn`, `vn`, `an`, `pttype`, `vstdate` ส่วนชื่อกว้าง ๆ เช่น `id`, `name`, `status` จะเติมหัวเรื่องของตารางให้ เช่น `name` ในตารางแผนก = "ชื่อแผนก" (หัวเรื่องมาจากท่อนแรกของคำอธิบายตาราง หรือแปลจากชื่อตาราง)
3. **ตารางอ้างอิง** คอลัมน์ที่มี "อ้างอิงไปที่" อยู่แล้ว เช่น foreign key ได้ความหมายจากตารางปลายทาง
4. **แปลจากชื่อ** แยกชื่อเป็นคำแล้วแปล เช่น `photo_id` = รหัสรูปภาพ, `refer_hospital_code` = รหัสโรงพยาบาลส่งต่อ, `last_visit_date` = วันที่การมารับบริการล่าสุด, `dx1` = รหัสโรค (ICD-10) ลำดับที่ 1 แม่นน้อยกว่าวิธีอื่น ถ้าแปลไม่ได้เลยสักคำจะไม่เสนอ

เพิ่มคำได้ที่ค่าคงที่ `DICT` (ชื่อเต็ม), `WORDS` และ `WORDS2` (คำที่ใช้แปลส่วนของชื่อ) ใน `src/Guesser.php`

### ผู้ใช้ออนไลน์

แถบด้านซ้ายแสดงว่าใครเปิดระบบอยู่และกำลังดูโปรเจ็คไหน กดที่ชื่อโปรเจ็คของคนอื่นเพื่อตามไปดูได้ หน้าเว็บรายงานตัวทุก 30 วินาที ผู้ที่ปิดหน้าไปโดยไม่กดออกจากระบบจะหายจากรายชื่อภายในราว 2 นาทีครึ่ง

ที่เก็บคือคอลัมน์ `last_seen_at`, `last_seen_project` ของตาราง `users` ระบบเพิ่มให้เองตอนมีผู้เปิดหน้าเว็บครั้งแรก ถ้าผู้ใช้ฐานข้อมูลของระบบไม่มีสิทธิ์ `ALTER` แถบซ้ายจะแจ้งว่า "ยังแสดงผู้ใช้ออนไลน์ไม่ได้" ให้รัน `database/migrate_20261110_online.sql` หนึ่งครั้ง

### การซิงค์ทำงานเบื้องหลัง

กด "ซิงค์โครงสร้าง" แล้วหน้าเว็บได้คำตอบทันที งานทำต่อบนเซิร์ฟเวอร์ แถบสีเหลืองแสดงขั้นตอนและเวลาที่ใช้ ปิดหน้าหรือเปลี่ยนโปรเจ็คได้ กลับมาเมื่อไรก็เห็นสถานะล่าสุด

- กด "ยกเลิก" ได้ระหว่างทาง ข้อมูลเดิมจะไม่ถูกเปลี่ยน (บันทึกทั้งชุดในครั้งเดียวตอนจบ)
- โปรเจ็คหนึ่งมีงานซิงค์ได้ทีละงาน
- ผลของทุกครั้งดูได้ที่ปุ่ม "ประวัติ"

วิธีทำงานเบื้องหลังมี 2 แบบ:

| แบบ | ตั้งค่า | เหมาะกับ |
|---|---|---|
| ทำต่อในคำขอเดิมหลังตอบกลับ (ค่าเริ่มต้น) | ไม่ต้องตั้ง | ใช้ได้ทันที แต่ยังอยู่ใต้เวลาจำกัดของเว็บเซิร์ฟเวอร์ (เช่น FcgidBusyTimeout, request_terminate_timeout) |
| แยกเป็น process ของ PHP CLI | ใส่ `'php_cli' => 'C:/xampp/php/php.exe'` ใน `config/config.php` | ฐานข้อมูลใหญ่ ไม่ขึ้นกับเวลาจำกัดของเว็บเซิร์ฟเวอร์ |

ถ้าซิงค์แล้วขึ้น "งานหยุดกลางทาง" แปลว่าโดนเว็บเซิร์ฟเวอร์ตัดเวลา ให้ตั้ง `php_cli`

### ซิงค์อัตโนมัติจาก command line

```
php cli/sync.php hosxp      ซิงค์โปรเจ็คเดียว
php cli/sync.php --all      ซิงค์ทุกโปรเจ็คที่ตั้งค่า connection ไว้
```

ตั้งใน Task Scheduler (Windows) หรือ cron (Linux) ให้ทำงานทุกคืนได้

### ภาระต่อฐานข้อมูลต้นทาง

การซิงค์อ่านเฉพาะ `information_schema` ไม่อ่านข้อมูลในตาราง ขนาดข้อมูลจึงไม่มีผล สิ่งที่มีผลคือจำนวนตาราง ค่าเริ่มต้นไม่อ่านจำนวนแถวโดยประมาณ เพราะทำให้ MySQL ต้องเปิดทุกตารางเต็มรูปแบบ ถ้าต้องการให้ใส่ `'read_row_estimate' => true` ใน config

### การซิงค์ทำอะไรกับข้อมูลเดิม

| ข้อมูล | เมื่อซิงค์ซ้ำ |
|---|---|
| ชนิดข้อมูล คีย์ ค่าเริ่มต้น index comment ในฐานข้อมูล | เขียนทับด้วยค่าจากฐานข้อมูลจริง |
| ความหมาย ค่าที่เป็นไปได้ หมายเหตุ กลุ่มงาน | ไม่แตะ |
| ช่องความหมายที่ยังว่าง แต่ฐานข้อมูลมี comment | เติมด้วย comment นั้น |
| ความหมายที่ระบบเดาไว้ แต่ฐานข้อมูลมี comment | แทนด้วย comment (comment เชื่อได้กว่าการเดา) |
| ความหมายที่มาจาก comment รุ่นก่อน แล้ว comment ถูกแก้ | ปรับตาม comment ใหม่ |
| ความหมายที่คนหรือ Claude เขียนในระบบนี้ | ไม่แตะ แม้ฐานข้อมูลจะมี comment |
| ตาราง/คอลัมน์ที่หายไปจากฐานข้อมูล | ทำเครื่องหมาย "ถูกลบ" คำอธิบายยังอยู่ |

## โครงสร้างไฟล์

```
index.php            หน้าเว็บ
api.php              web service (JSON)
assets/              app.js, app.css
cli/sync.php         ซิงค์จาก command line และตัวทำงานเบื้องหลัง
src/                 bootstrap.php, Introspector.php (อ่านโครงสร้าง), Dictionary.php (จัดเก็บ/นำเข้า/ส่งออก), Guesser.php (เดาความหมาย/ตีความจากข้อมูลจริง)
config/config.php    ค่าเชื่อมต่อและ app_key
database/schema.sql  สคริปต์สร้างฐานข้อมูล (migrate_*.sql สำหรับฐานข้อมูลที่ติดตั้งไว้ก่อน)
```

## ตารางในฐานข้อมูล

| ตาราง | เก็บอะไร |
|---|---|
| `projects` | โปรเจ็ค ค่า connection (รหัสผ่านเข้ารหัส AES-256-GCM) และ hash ของ API key |
| `dd_tables` | ตาราง/วิวของแต่ละโปรเจ็ค พร้อมคำอธิบาย |
| `dd_columns` | คอลัมน์ โครงสร้าง ความหมาย ตัวอย่างข้อมูล และข้อเสนอรอพิจารณา |
| `dd_indexes` | index ของแต่ละตาราง |
| `sync_logs` | ประวัติการซิงค์ นำเข้า เดาความหมาย และโคลน |
| `users` | ผู้ใช้หน้าเว็บ |

## ความปลอดภัย

- ใช้ผู้ใช้ฐานข้อมูลต้นทางที่มีสิทธิ์ `SELECT` อย่างเดียว การซิงค์อ่านเฉพาะ catalog ของระบบ ส่วนปุ่ม "ตีความจากข้อมูลจริง" อ่านแถวล่าสุดของตารางเฉพาะตอนมีคนกด (ดูหัวข้อเดาความหมาย) ใช้ได้เฉพาะผู้ใช้ที่เข้าสู่ระบบหน้าเว็บ API key เรียกไม่ได้
- โฟลเดอร์ `config/`, `src/`, `cli/`, `database/` มี `.htaccess` กันการเข้าถึงสำหรับ Apache ถ้าใช้ nginx หรือ IIS ให้ตั้งกฎปิดโฟลเดอร์เหล่านี้เอง
- API key ผูกกับโปรเจ็คเดียว อ่านและนำเข้าคำอธิบายได้ แต่แก้ค่า connection ซิงค์ หรือลบโปรเจ็คไม่ได้
- ถ้าเปิดใช้นอกวง LAN ควรใช้ HTTPS
